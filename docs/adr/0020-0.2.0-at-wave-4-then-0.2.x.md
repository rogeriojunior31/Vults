# 0020. Releases: small and frequent

**Status:** Accepted, 2026-10-10. Consolidated on 2026-10-12 from 0007 and 0015.
Amended on 2026-10-16 by [0031](0031-tasks-leave-vults.md), and on 2026-10-26 for the 0.1.9 stabilization release.

## Context

The first plan gave each version up to 0.5 one theme, which kept users waiting months for work
ready in days and made a version number promise a whole theme. The plan that followed
(`docs/dev/plan-zeca.md`) grew: Zeca's memory and work, a companion that speaks when it should, an
Android phone, and leftovers. Holding 0.2.0 until all of it is done would keep the Operations
milestone waiting for work it does not need.

## Decision

- The first release is **0.1.0**.
- Releases stay small and frequent. A patch number does not mean "fixes only", and may pass 9.
- The next release is **0.1.9**, a stabilization release from the current `main` with the work
  already merged there: N0 to N3, agent profiles and specialist Chat, GitHub through GH8 and the
  Dictation workspace refinement. It also includes the release fixes accepted before the tag.
  No stage is removed from this source snapshot to recreate the old version-to-stage mapping.
- The [roadmap](../dev/ROADMAP.md) owns the remaining release gates. Later versions are chosen at
  their release gate from a bounded, validated set of changes; one phase does not automatically
  reserve a version. The 2026-10-16 mapping of N0 to N4 to fixed version numbers is superseded.
- Selecting 0.1.9 does not bump package versions, create a tag or authorize publication. Those
  actions belong to REL-2 after R3, the required native acceptance and green CI, including Security.
  Experimental features retain their existing opt-in and preview status until their own gates pass.
- Every release tag follows the human R3 smoke in the real app on the UI refined by N1
  ([0031](0031-tasks-leave-vults.md)). The wave 4 and U1/U13 gates no longer determine the tag.
  Native acceptance and automated CI remain required, separate from R3.
- Linux first through 0.2.x, with Android as the one exception
  ([0004](0004-a-human-answers-permissions.md)). Windows and macOS betas may land late in 0.2.x
  (plan-zeca X7); their full support comes after.
- 1.0 means "done for Linux".

## Consequences

- Users get each feature when it is ready; the changelog is per release.
- Remaining features ship when their roadmap gates pass; old milestone promises do not make
  them requirements for the next release or certify experimental behavior.
- The active roadmap points at this record; older specifications preserve the former stage plan
  as history. Tasks and their review are no longer release requirements; `/continue`, spend and
  the budget remain covered by R3.
- R3 and native acceptance are recorded against the release candidate's actual source revision.
  Choosing a version or passing automated tests does not complete a desktop acceptance gate.

## History

- 0007, 2026-10-04: the first release is 0.1.0; one theme per version up
  to 0.5 (dropped by 0015).
- 0015, 2026-10-04: small 0.1.x releases, with
  everything planned by 0.2.0 (later narrowed to the wave 4 gate).
- 2026-10-16, [0031](0031-tasks-leave-vults.md): remove Tasks from the gate; release 0.1.9 after
  N0/N1 and 0.2.0 after N2, followed by N3 and N4, each after R3.
- 2026-10-26, REL-1: the owner selected 0.1.9 as the next stabilization release from current
  main. Supersede fixed stage-to-version numbers; retain R3, native acceptance and green CI before
  REL-2 changes package versions, tags and publishes. No feature's preview gate is waived.
