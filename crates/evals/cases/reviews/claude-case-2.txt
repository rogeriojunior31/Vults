Findings, most serious first:

1. **`dates.py:6` (`return year % 4 == 0 and year % 100 != 0`): the 400-year rule is missing, so `is_leap` gives wrong answers for century years divisible by 400.** The Gregorian rule is: divisible by 4, except centuries, unless divisible by 400. The expression omits the last clause, so it returns `False` for 2000, 1600, 2400, 0 and -400, which are all leap years. I checked this by calling the function directly with `python3 -I`: 2000, 1600, 2400, 0 and -400 all returned `False`. The other cases I checked (1900, 2023, 2024, 2100, 1996, 1, -4, -100) were correct. This breaks the criterion "is_leap(year) follows the Gregorian rules". Fix: `return year % 4 == 0 and (year % 100 != 0 or year % 400 == 0)`.

So "run the project's tests" had nothing to run, and the bug in item 1 went unnoticed. A test covering 1900, 2000, 2023, 2024 and 2100 would have caught it.
